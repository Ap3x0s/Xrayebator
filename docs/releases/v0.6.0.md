# Xrayebator v0.6.0 — панель научилась отзывать доступ и выключать профили по сроку

> Обновление серверного менеджера и **Xrayebator Desktop GUI**. Ставится поверх `v0.5.5` — миграции доделают всё сами, перенастраивать серверы не нужно.

## Если объяснить в двух словах

До сих пор панель умела создавать ключи, но не умела с ними обращаться, когда что-то пошло не так. Если ссылка на подписку утекла в чат — вы могли только удалить профиль целиком и заново выдать всем новые ссылки.

`v0.6.0` закрывает три дыры:

1. **Revoke подписки** — кнопка у каждого профиля. «Только новая ссылка»: меняются токен и URL, маршруты и ключ те же, скачанные конфиги продолжают работать. «Полный отзыв»: меняются и uuid — уже скачанные конфигурации отваливаются немедленно. Только полный отзыв реально закрывает доступ по утёкшей ссылке.
2. **Срок действия профиля** — у профиля появляется дата окончания. Сервер сам отключает клиента по наступлении срока и включает обратно при продлении; переимпортировать подписку клиентам не нужно. В GUI — дата-чип с предупреждением за три дня, календарь выбора и быстрые пресеты +7/+30/+90/+365.
3. **Истёкший профиль больше не выдаёт маршруты** — подписка отвечает честным `410 Gone` вместо «рабочей на вид» ссылки, которая всё равно не подключится.

```text
┌─────────────────────────┐
│   Xrayebator Desktop    │
│  профиль «друг»         │
│   до 31.12.2026 ⚠ за 3 дня
│   [Revoke] [Срок] [QR]  │
└───────────┬─────────────┘
            │
   revoke: новый токен (+uuid при полном)
   срок:   таймер снимает клиента с inbound → 410
   продлил: тот же uuid вернулся → 200
```

## Что нового

### 1. Revoke: два режима вместо «удали и пересоздай»

Кнопка у профиля открывает меню:

- **Только новая ссылка** — перевыпуск `sub_token`. Старый URL мгновенно мёртв, маршруты, порты и ключ не меняются: тем, кому ссылка не нужна, ничего не мешает.
- **Полный отзыв** — новый токен **и** новый uuid во всех маршрутах профиля. Устройства, уже скачавшие конфиг, отключаются — это единственный способ реально перекрыть доступ по утёкшей ссылке. Требуется второе подтверждение; после успеха панель сразу показывает новую ссылку.

Команда: `xrayebator profile-revoke --name ИМЯ [--full]`. Транзакция выстроена так, чтобы конфиг и профиль никогда не разъехались: сначала config + валидация + рестарт Xray, затем profile JSON; при сбое второй части конфиг откатывается из бэкапа.

### 2. Сроки действия: сервер выключает сам

- CLI: `profile-create --expire ДАТА` (срок сразу при создании), `profile-expire --name ИМЯ --expire ДАТА|epoch|none`, `expire-check`;
- в profile JSON поле `.expire` (epoch-секунды, `0` = бессрочно);
- **принуждение на сервере**: systemd-таймер `xrayebator-expire.timer` каждые 10 минут вызывает `expire-check` и снимает клиента с inbound'ов. GUI при этом не нужен — срок сработает, даже если панель закрыта;
- продление возвращает **того же клиента**: снимок сохраняется в `.expire_clients`, поэтому uuid и все выданные ранее ссылки остаются валидны;
- дата без времени действует включительно: срок «30 сентября» живёт до `23:59:59` по часам сервера;
- подписка `profiles` отдаёт рядом с epoch ещё и `expire_date` — календарную дату в зоне сервера. Поэтому на компьютере в другом часовом поясе «до 30.09» не превращается в «до 29.09».

Почему inbound не удаляется: пересоздание инбаунда меняет Reality shortId, и все когда-либо выданные ссылки умерли бы. Отключение клиента — точечная правка, маршруты живут.

### 3. 410 Gone для истёкших

Раньше просроченный профиль продолжал отдавать список ссылок: клиент импортировал «рабочий» конфиг, который не подключается, — и это выглядело как баг VPN. Теперь subhttp проверяет и флаг отключения, и сам срок (таймер ходит раз в 10 минут — до его срабатывания срок уже мог наступить) и отвечает `410 Gone` с телом `Profile expired or disabled`. Миграция `subhttp_expired_410_2026` перегенерирует обработчик на существующих серверах — после апдейта поведение включается само.

### 4. Свой календарь в панели

Выбор срока больше не системный `input[type=date]`: тематический календарь с квадратными днями, подсветкой «сегодня», выбранный день — акцентным тоном; прошлые даты недоступны, листание назад упирается в текущий месяц, шапка никуда не прыгает при смене месяца.

### 5. Понятные ошибки вместо «код 1»

CLI-команды теперь показывают настоящую причину: она парится из stderr, а если stderr пуст — из stdout (часть ошибок менеджер печатает именно туда). Неизвестная команда на старом сервере получает подсказку: «обновите Xrayebator», — а не пустой код возврата.

### 6. Ветка обновления закрепляется

Раньше `xrayebator update <ветка>` заменял скрипт, но не запоминал ветку: следующее обновление из кнопки «Обновить Xrayebator» молча возвращало сервер на `main`, и свежие команды исчезали. Теперь ветка пишется в `.current_branch` после успешного self-update, имя ветки валидируется до подстановки в URL. Это чинит ситуацию, из-за которой «обновил — а фич нет».

## Что ещё попало в ветку

- **Убран `docs/superpowers`** — агентские планы разработки, не документация продукта.
- **Документация приведена в соответствие** на трёх языках: новые команды в CLI-справочнике, контракт `expire_date`, тон-подсветка «скоро истекает», предупреждение о старом сервере без поддержки сроков, раздел troubleshooting про подписку с кодом 410.
- **bypass не менялся**: серверная реализация и меню остаются как были (пункт 7); GUI-обход домена — не часть этого релиза.

## Насколько это проверено

Автоматически:

- Bash-валидация: **28 скриптов**, включая новые `test-profile-revoke-expire-cli.sh` (revoke обоих режимов, сроки, идемпотентный `expire-check`, JSON-чистота stdout, `expire_date` при разных часовых поясах, даты с ведущими нулями) и `test-update-branch-pinning.sh` (закрепление ветки);
- GUI: Vitest — тесты календаря и разбора срока; typecheck и сборка — чистые;
- CI на Ubuntu/Windows/macOS — зелёный.

Живо на VPS (Debian 13): выставление срока в прошлом → `410` с телом `Profile expired or disabled` и отключение клиента, снятие срока → `200` с теми же маршрутами; `revoke --full` меняет uuid на всех портах общего inbound, чужие клиенты на порту не затронуты; кнопка «Обновить» с закреплённой ветки фичи не сбрасывает.

## Полевые заметки (опыт live-сессий, без личных данных)

Пара находок, которые пригодятся всем, кто настраивает Reality, — они же причины «не работает, хотя всё правильно»:

- **Reality требует от dest TLS1.3 с key_share X25519.** Часть гос-доменов на отдельных CDN-edge отвечает `ECDH prime256v1` — и маршруты с таким dest молча деградируют (`target sent incorrect server hello`). Проверка с самого VPS: `echo | openssl s_client -connect хост:443 -tls1_3` и смотреть `Server Temp Key:`. Поведение зависит от того, до какого edge дотянулся конкретный сервер, и меняется со временем.
- **PQ-xhttp требует парную `encryption=`-строку.** Клиент с `encryption=none` на PQ-маршруте висит без строк в логе. В тело подписки PQ намеренно не кладётся (URL ~2 КБ) — это не баг, а размер.
- **Сначала достижимость, потом протоколы.** Если прямой ping и TCP до подписки/портов не проходят, IP блокируется выше по пути — никакая правка SNI/dest не поможет. Порядок диагностики, экономящий часы: доступность → контракт подписки (200/404/410) → туннели.
- **Гигиена тестов:** правки состояния — только через CLI менеджера (бэкап+валидация+откат автоматом), debug-настройки откатывать из тех же бэкапов; скрипты с реальными ключами и дампы не оставлять ни в репо, ни на сервере.

## Важно перед обновлением

### Требование к серверу

- Debian 12/13 или Ubuntu 22.04/24.04, systemd, bash, root/sudo;
- миграции догонят состояние автоматически при первом запуске меню или quickstart.

### Breaking changes

Их нет. Поля `.expire`/`expire_date` — только добавлены; старые профили без срока работают как раньше; команды `profiles` совместимы.

### Честные ограничения

- принуждение сроков идёт с задержкой до 10 минут (период таймера), а снятие срока через CLI/GUI — немедленное;
- `expire_supported` нет у серверов старше этого релиза: панель честно предупредит, что сервер устарел, а не покажет «бессрочно»;
- `probe-test` проверяет TLS1.3 dest, но не тип key_share — см. Полевые заметки выше.

## Как обновиться

### Сервер

```bash
sudo xrayebator update main
```

### Xrayebator Desktop GUI

1. Скачайте пакет для своей ОС из GitHub Release.
2. Установите поверх предыдущей версии — карточки серверов сохранятся.
3. Откройте «Настройки сервера»: у профилей появятся кнопки Revoke и Срок.

## Сборка

Релиз собирается нативно для трёх систем:

- Windows — `Xrayebator-0.6.0-win.exe`;
- macOS Apple Silicon — `Xrayebator-0.6.0-mac-arm64.dmg` и `.zip` (ZIP нужен встроенному автообновлению);
- Linux — `Xrayebator-0.6.0-linux.AppImage`.

Перед сборкой на Ubuntu прогоняются typecheck, unit-тесты и полный набор Bash-валидаций (28 скриптов).
